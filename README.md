# timetable_upload — перенос расписания из ХроноГраф 3.0 Мастер в МЭШ

Набор инструментов, который читает файл расписания `.chngf` (ХроноГраф 3.0
Мастер) и переносит занятия в МЭШ (school.mos.ru) через его учительский API:
уроки — в «Расписание по классам», занятия внеурочной деятельности
(«Разговоры о важном», «Россия — мои горизонты», кружки) — в «Расписание
внеурочной деятельности».

Состояние: разбор `.chngf` сверен с отчётами самой программы; загрузчик
проверен на реальном API школы (учебный год 2026/27, неделя 39): 2226 уроков
и 268 занятий ВД из файла созданы, повторный запуск ничего не меняет, откат
по журналу работает.
Вход — через окно mos.ru во встроенном браузере (токен `aupd_token`
перехватывается сам) или вставкой токена вручную (см. «Вход»).

## Установка

Готовые сборки (Windows, Linux) лежат в
[Releases](../../releases): `timetable-upload-gui` — окно, `timetable-upload` —
командная строка; ставить ничего не нужно.

Из исходников:

```sh
pip install -e .            # зависимость только requests
pip install -e '.[gui]'     # + PySide6 для графического интерфейса
pip install -e '.[test]' && pytest -q         # тесты
```

Запуск: `python -m timetable_upload <команда>` (или `timetable-upload` после установки);
графический интерфейс — `python -m timetable_upload gui` (или `timetable-upload-gui`).

## Где лежат данные

Всё, что программа создаёт, хранится в одной папке пользователя:

| система | папка |
|---|---|
| Windows | `%APPDATA%\timetable_upload` |
| Linux | `~/.local/share/timetable_upload` |
| macOS | `~/Library/Application Support/timetable_upload` |

Внутри: `cache/` — справочники МЭШ, `mapping.json` — сопоставление,
`aupd_token.txt` и `aupd_refresh_token.txt` — токены, `upload.journal.jsonl` —
журнал созданных занятий, `logs/` — лог интерфейса, `web/` — cookie встроенного
браузера (сессия mos.ru). Команда `timetable-upload paths` печатает пути; в
окне они показаны в «Дополнительно…» на вкладке «Данные и вход» (там же
кнопка «Открыть папку»).
Другая папка — переменная окружения `TIMETABLE_UPLOAD_HOME`; каждый путь по
отдельности — параметры `--cache`, `--mapping`, `--token-file`, `--journal`.

## Графический интерфейс

Окно с четырьмя вкладками повторяет порядок работы из командной строки, но
всё сопоставление правится в таблицах, а перенос настраивается флажками.

1. **Данные и вход** — файл `.chngf` и сведения о нём; «Войти через
   mos.ru…» (окно входа, токен сохраняется сам), «Проверить вход»,
   «Загрузить справочники из МЭШ» (только чтение). Редко нужное — в окне
   «Дополнительно…»: токен вручную + «Сохранить в файл», id профиля,
   учебный год, понедельник 1-й недели, «Забыть сессию mos.ru», папка данных
   и пути к файлам программы (сопоставление, кэш, журнал, токен). Всё
   запоминается между запусками.
2. **Сопоставление** — кнопка «Автосопоставление» (то же, что `match`) и
   таблицы «Классы», «Предметы», «Учителя», «Кабинеты», «Группы»,
   «Настройки». В каждой — поиск и фильтр «только проблемы»; проблемные
   строки подкрашены (красный — не сопоставлено, жёлтый — проверьте).
   Класс/учитель/кабинет выбирается из выпадающего списка с поиском по
   подстроке; предметы — двойным щелчком (список с флажками: предметы МЭШ и
   курсы ВД; отмеченные нумеруются — это приоритет, кнопки «Выше»/«Ниже»
   переставляют); флажок «Переносить» = `ignore_classes` / `ignore_subjects`.
   В «Группах» на каждую классогруппу — по строке на каждый приоритет её
   предмета: какая группа МЭШ выбрана автоматически и почему, уроков в
   неделю и часов группы по нагрузке; если уроков больше часов, а следующего
   приоритета нет, строка жёлтая («лишние встанут сверх часов»). Двойной
   щелчок по строке открывает окно выбора группы МЭШ для этого приоритета
   (таблица групп класса с поиском, учителями, часами, числом учеников и
   отметкой «уже задана вручную для…»; переключатель «только по предмету»;
   кнопка «Автоматически» убирает ручной выбор) — это `groups` в `mapping.json`.
   «Настройки» — синонимы предметов, длительности ВД и регулярные выражения.
   «Сохранить» пишет `mapping.json` (тот же формат, что и у `match`).
3. **Перенос в МЭШ** — отметить недели (даты показаны), при желании
   уточнить даты, дни недели, классы (тот же синтаксис, что у `--classes`,
   или кнопка «Выбрать…»), вид занятий и флажок «удалять лишнее»
   (`--replace`), число одновременных запросов («Параллельно», см.
   `--workers`). «Показать план» строит план без сервера, «Сравнить с
   сервером» — читает занятия с сервера и показывает, что будет создано,
   удалено, что отличается; «Загрузить в МЭШ…» после подтверждения
   применяет план (с прогрессом; ошибки по каждому занятию — в дереве и в
   журнале сообщений). «Посчитать занятия на сервере» заполняет столбец
   с числом уроков/ВД по неделям. «Сохранить в файл…» записывает то, что
   показано в дереве — план или итоги загрузки со списком ошибок — в
   `.csv` (таблица для Excel: по строке на занятие с действием, полями
   ХроноГрафа и id МЭШ) или `.txt` (текстовый отчёт, как у команды
   `plan`).
4. **Откат** — записи журнала созданных занятий с фильтром; отмеченные
   удаляются с сервера (`undo`).

Все сетевые операции идут в фоне; журнал сообщений внизу окна дублирует
вывод команд. Долгие операции (загрузка, откат, сравнение, подсчёт) можно
прервать кнопкой «Остановить» в строке состояния: задача завершается после
текущего запроса, всё уже созданное остаётся на сервере и в журнале отката,
а повторное «Сравнить с сервером» покажет, что осталось.

## Вход

API принимает токен `aupd_token` — тот, что после входа в school.mos.ru лежит
в одноимённой cookie (он же `Authorization: Bearer …` в запросах). Получить
его можно двумя способами.

**Через окно mos.ru.** Кнопка «Войти через mos.ru…» на вкладке «Данные и
вход», команда `python -m timetable_upload login` или `timetable-upload-gui
--login`: открывается встроенный браузер со страницей входа school.mos.ru →
login.mos.ru; вход как обычно (пароль, код из СМС и т. п.). Когда
school.mos.ru поставит cookie `aupd_token`, окно закроется само, токен будет
записан в `aupd_token.txt`, а refresh-токен (cookie `aupd_refresh_token`,
30 дней) — в `aupd_refresh_token.txt`. Cookie mos.ru остаются во встроенном браузере
(`web/` в папке данных), так что в пределах сессии mos.ru повторный вход
проходит без пароля; «Забыть сессию mos.ru» их удаляет (например, чтобы войти
под другим аккаунтом). Нужен QtWebEngine — он входит в обычный `pip install
PySide6` и в собранный `timetable-upload-gui`; консольный `timetable-upload`
без Python-окружения его не содержит — используйте `timetable-upload-gui
--login`.

**Вручную.** После входа в school.mos.ru скопируйте cookie `aupd_token`
(инструменты разработчика → Application → Cookies) в файл `aupd_token.txt`
в папке данных, в поле «Токен вручную» (окно «Дополнительно…» на вкладке
«Данные и вход») или в переменную `MESH_TOKEN`.

Профиль сотрудника и текущий учебный год определяются автоматически
(`POST /api/ej/acl/v1/sessions`, `GET …/academic_years?only_current_year=true`);
если профилей несколько — `--profile-id`, другой год — `--academic-year 2025/26`.

```sh
python -m timetable_upload login                 # окно входа, токен — в файл
python -m timetable_upload check-auth            # кто я, какой год
```

Токен живёт сутки, но обновляется сам: перед работой с сервером (и при ответе
401) программа делает `POST /v3/token/refresh` с refresh-токеном и переписывает
оба файла — refresh-токен одноразовый, сервер каждый раз выдаёт новый (старый
отвечает `403 token_revoked`). Пока программа запускается хотя бы раз в 30 дней,
входить заново не нужно; иначе — «Войти через mos.ru» ещё раз. Вставленный
вручную токен без refresh-токена живёт сутки. `check-auth` печатает сроки
действия обоих токенов.

## Порядок работы

1. **Посмотреть файл**
   ```sh
   python -m timetable_upload info school.chngf
   python -m timetable_upload dump school.chngf --classes 11в          # текст
   python -m timetable_upload dump school.chngf --format csv > all.csv  # csv/json
   ```

2. **Загрузить справочники МЭШ** (классы, группы с учениками, учителя,
   кабинеты, расписания звонков, недели, курсы и группы внеурочной
   деятельности) в каталог-кэш — только чтение:
   ```sh
   python -m timetable_upload fetch
   python -m timetable_upload weeks --file school.chngf --online   # что уже лежит по неделям
   ```
   Кэш привязан к учебному году: если при входе выбран другой год (наступил
   новый или задан `--academic-year`), команды, работающие с сервером,
   откажутся использовать старый кэш — нужен новый `fetch`.

3. **Сопоставить** сущности ХроноГрафа с МЭШ:
   ```sh
   python -m timetable_upload match school.chngf
   ```
   Команда пишет `mapping.json` в папку данных и печатает отчёт. Классы, учителя, кабинеты и
   большинство предметов сопоставляются автоматически; всё, что осталось
   (`null` в файле), заполняется руками — в отчёте даны варианты с id.
   Повторный `match` проверяет заполненное и не трогает уже сопоставленное.

   Структура `mapping.json`:
   * `classes` — класс ХроноГрафа → название класса МЭШ («11в» → «11-В»);
   * `subjects` — предмет → **список** названий предметов МЭШ или курсов
     внеурочной деятельности **в порядке приоритета** («Алгебра» →
     `["Алгебра", "Алгебра и начала математического анализа"]`; какой из них
     есть у данного класса, решается автоматически). Если в классе есть группы
     по нескольким названиям, уроки недели ставятся в группу первого, пока не
     исчерпаны её часы, затем — второго и т. д. (см. «Часы групп» ниже);
   * `teachers` — ФИО → id профиля учителя;
   * `rooms` — кабинет → id кабинета; `room_prefixes` — префикс кабинета
     (`""`, `"к"`, `"_"`, …) → id здания, по нему автоматически подбираются
     номера;
   * `groups` — `"класс|предмет|номер группы"` → id группы МЭШ (обычной или
     ВД) для первого приоритета, `"класс|предмет|номер группы|2"` — для
     второго и т. д.; заполняется там, где группу не удалось выбрать однозначно;
   * `ignore_subjects`, `ignore_classes` — что не переносить;
   * настройки автосопоставления — при первом `match` копируются из
     `timetable_upload/defaults.json` и дальше правятся в `mapping.json`:
     `subject_synonyms` (нормализованное название предмета ХроноГрафа →
     названия предметов/курсов МЭШ, например `"физ ра": ["Физическая культура"]`),
     `ec_durations` (допустимые длительности занятий ВД), `ec_course_suffix`
     (regex хвоста с классами в названии курса ВД), `group_ordinal_suffix`
     (regex номера подгруппы «… 2гр» в названии группы МЭШ).

   Как выбирается группа МЭШ для занятия: класс + предмет → кандидаты среди
   обычных групп класса, а если таких нет — среди групп внеурочной
   деятельности этого класса (название курса ВД берётся без хвоста с
   классами: «Разговоры о важном 2-4» → «Разговоры о важном»); если
   кандидатов несколько — по учителю; для «потоков» (несколько классов на
   одном уроке) — метагруппа с тем же набором классов; для подгрупп одного
   учителя («Технология/1» и «/2») — по составу учеников: подгруппа,
   идентичная по ХроноГрафу уже сопоставленной («Английский/1»),
   сравнивается со списками учеников групп МЭШ; в последнюю очередь — по
   номеру группы («… 2гр» в названии, помечается «проверьте!»). Всё это —
   отдельно для каждого названия МЭШ из `subjects`; какая из подобранных
   групп достанется конкретному уроку, решают часы (см. «Часы групп»).

4. **Посмотреть план** и сравнить с сервером:
   ```sh
   python -m timetable_upload plan school.chngf --weeks 16 --classes 11в,11Б
   python -m timetable_upload plan ... --weeks 16 --online
   ```
   Для каждого занятия показывается, во что оно превращается (группа, учитель,
   кабинет, звонок или время, дата), и почему пропущены остальные.
   `--export план.csv` дополнительно записывает план в файл: `.csv` —
   таблица для Excel (разделитель `;`, UTF-8 с BOM), любое другое
   расширение — тот же текстовый отчёт.

   Что именно переносить (одинаково для `plan`, `upload`, `undo`):
   * `--weeks 16 | 16-20 | 16,18-20` — учебные недели;
   * `--dates 2027-05-24 | 24.05.2027 | 2027-05-24..2027-05-28` — конкретные
     даты (недели вычисляются сами, `--weeks` можно не указывать);
   * `--days пн,ср | 1-3 | пн-пт` — дни недели внутри выбранных недель;
   * `--classes 5а,5б | 5 | 10*` — имена классов, вся параллель, шаблон;
   * `--only oo` / `--only ec` — только уроки или только внеурочная деятельность.

   Например, один день одного класса: `--dates 2027-05-26 --classes 2а`.

5. **Загрузить** (без `--apply` — пробный прогон):
   ```sh
   python -m timetable_upload upload school.chngf --weeks 16 --classes 11в,11Б --apply
   ```
   Загрузка идемпотентна: совпадающие занятия на сервере не трогаются,
   недостающие создаются. Без `--replace` **ничего не удаляется** (занятия с
   другим учителем/кабинетом лишь показываются как «отличаются»); с
   `--replace` удаляются занятия выбранных классов на выбранные даты, которых
   нет в файле, и пересоздаются отличающиеся. Всё созданное пишется в журнал
   `upload.journal.jsonl`; `undo --weeks 39 --apply` удаляет ровно эти
   занятия (например, после пробной загрузки на дальнюю неделю), при
   необходимости — только часть: `undo --dates 2027-05-26 --classes 2А --only oo --apply`
   (`-v` перечисляет записи). Ни `plan`/`upload`, ни `undo` не работают без
   ограничения по времени — `--weeks` и/или `--dates` обязательны (в окне —
   отмеченные недели или даты), чтобы нельзя было случайно тронуть весь год.
   Ошибки сервера печатаются по каждому занятию, остальные продолжают
   загружаться; если ответ сервера оборвался, факт создания перепроверяется.
   Занятия отправляются по нескольку одновременно (`--workers N`, по умолчанию
   8, у `undo` тоже): сначала все удаления, потом все создания. Если сервер
   отвечает 429 («слишком много запросов»), запрос повторяется с паузой, а в
   выводе появляется предупреждение — тогда `--workers` стоит уменьшить.

6. **Размножить на другие недели** — либо тем же `upload --weeks 17-34`
   (по одному запросу на занятие), либо штатным копированием МЭШ:
   ```sh
   python -m timetable_upload copy school.chngf --from-week 16 --to-weeks 17-34 --classes 11в,11Б
   ```

## Что нужно знать

* **Недели.** Неделя N в МЭШ — N-я неделя от недели, содержащей дату начала
  учебного года (для 2026/27 неделя 1 начинается 31.08.2026). Если нужно
  иначе — `--week1-monday ГГГГ-ММ-ДД`. Команда `weeks --online` показывает
  даты недель и сколько занятий уже лежит на сервере (счётчик в списке недель
  и выборка без фильтра по классам у сервера пустые — не полагайтесь на них).
  Для файла с двухнедельным циклом в нечётные недели МЭШ переносится первая
  неделя цикла, в чётные — вторая (в сводке плана это указано).
* **Часы групп.** Предмету ХроноГрафа можно сопоставить несколько названий
  МЭШ по приоритету (`subjects`, порядок в списке): например, «Информатика»
  → `["Информатика", "Технология"]`. Уроки недели в хронологическом порядке
  (пн 1-й урок → сб последний) идут в группу первого названия, пока не
  исчерпаны её часы на этой неделе, затем в группу второго и т. д.; если часы
  исчерпаны у всех, урок встаёт в группу первого приоритета сверх часов (в
  плане помечено). Часы группы на неделе — нагрузка учителя занятия в этой
  группе из справочника (`teacher_loads`; если у него записи нет — сумма по
  учителям группы; у групп ВД и групп без нагрузки лимита нет). Часы
  считаются по всей неделе, даже когда перенос ограничен датами или видом
  занятий, а при `--online` учитываются и занятия, которые уже лежат на
  сервере и после переноса останутся (все без `--replace`; с ним — вне
  выбранных дат). Группа, у которой учитель занятия не привязан, при
  распределении пропускается (в «Группах» это отмечено). Отчёт `match`
  предупреждает, где уроков в неделю больше часов группы первого приоритета.
* **Календарь.** На выходные и каникулы сервер занятия не принимает
  («Нельзя создавать урок расписания на выходной день»); у учителей на такие
  недели нет нагрузки — см. столбец в `weeks`.
* **Звонки.** Урок № k ставится на звонок с `study_ordinal = k` расписания
  звонков, назначенного классу на эту дату; если такого урока нет — занятие
  пропускается с пояснением.
* **Кабинеты.** Сервер требует кабинет у каждого урока. Если в ХроноГрафе
  кабинет не назначен или не сопоставлен, подставляется — как в веб-интерфейсе
  МЭШ — кабинет учителя в здании класса, иначе первый кабинет этого здания;
  в плане это помечено («подставлен «41»»). Такой кабинет — догадка: с
  кабинетом уже существующего на сервере занятия он не сравнивается, и
  `--replace` из-за него занятие не пересоздаёт (сравниваются только учитель и
  сопоставленный кабинет). У занятий ВД кабинет не обязателен, зато его
  занятость сервер проверяет («…в кабинете уже существуют уроки»), поэтому
  для ВД кабинет ставится только сопоставленный.
* **Внеурочная деятельность.** Занятие ВД задаётся не звонком, а временем:
  берутся границы звонка класса на этот урок, длительность должна быть 30, 35,
  40 или 45 минут (как в интерфейсе МЭШ). Сервер отвергает занятие, если
  учитель, ученики группы или кабинет в это время заняты. Расписание ВД на
  неделю (`ec_schedule`) создаётся автоматически, если его ещё нет.
* **Учителя.** Сервер принимает только учителя, привязанного к группе, и не
  принимает удалённые профили — такие занятия отсекаются заранее с указанием,
  кто стоит у группы в МЭШ (часто «Вакансия …»). Удалённые профили (их в
  справочнике может быть больше, чем действующих) нигде не участвуют: не
  предлагаются при сопоставлении, не считаются учителями групп, а старое
  сопоставление на удалённый профиль автосопоставление подбирает заново.
* **Конфликты.** «Для следующих учеников уже назначен урок» означает, что в
  МЭШ ученик состоит в обеих подгруппах, которые в файле идут одновременно, —
  это надо править в составах групп МЭШ.
* **Иностранные языки.** Если классогруппа привязана к иностранному языку,
  предметом считается название языка («Английский»).
* `DELETE /schedules/{id}` (очистка всей недели) в инструменте не используется:
  по захвату не ясно, ограничивается ли он классами пользователя.

## Сверка разбора с ХроноГрафом

`tools/compare_html.py отчёт.html файл.chngf` сравнивает разбор с HTML-отчётом
«Расписание классов» самой программы (Отчёт → Расписание классов →
«По отдельности», ФИО — все, кабинеты — все, вывод — HTML). На трёх
имеющихся файлах (2904, 3245 и 1017 занятий; сравниваются предмет, учитель,
группа и кабинет каждой ячейки) расхождений нет.

## Структура

```
timetable_upload/           пакет
  chngf.py                  разбор .chngf (описание формата — docs/chngf-format.md)
  mesh_api.py               клиент API МЭШ
  auth.py                   токены: хранение, срок действия, обновление по refresh-токену
  refdata.py                кэш справочников МЭШ
  mapping.py                сопоставление сущностей и выбор групп
  uploader.py               план, сравнение с сервером, применение, журнал, откат
  export.py                 выгрузка плана и итогов загрузки в CSV / текст
  cli.py                    команды
  defaults.json             настройки автосопоставления по умолчанию
  paths.py                  папка данных пользователя
  gui/                      графический интерфейс (PySide6): state.py — общее
                            состояние и пути, setup_tab.py, mapping_tab.py,
                            upload_tab.py, undo_tab.py, main_window.py,
                            common.py — фоновые задачи и редакторы ячеек,
                            web_login.py — окно входа через mos.ru (QtWebEngine)
tests/                      тесты (pytest); tests/data/demo.chngf — демонстрационный
                            файл из дистрибутива ХроноГрафа
tools/compare_html.py       сверка разбора с отчётом ХроноГрафа
docs/chngf-format.md        описание формата .chngf
packaging/                  сборка самостоятельных исполняемых файлов (PyInstaller)
.github/workflows/          CI (ruff + pytest) и сборка релизов
```

Тесты на реальном файле школы (`school.chngf` в папке данных) пропускаются,
если его нет; тесты окна входа (`tests/test_web_login.py`, локальный
HTTP-сервер вместо mos.ru) — если нет QtWebEngine. Проверка кода: `pip install ruff && ruff check` (настройки в
`pyproject.toml`).

## Сборка и выпуск

Локально: `pip install '.[gui]' pyinstaller && pyinstaller packaging/timetable_upload.spec`
— в `dist/` появятся `timetable-upload` и `timetable-upload-gui` (onefile).
Графический файл большой (в нём QtWebEngine — браузер для окна входа) и
распаковывается при каждом запуске несколько секунд.

Релиз собирает GitHub Actions (`.github/workflows/release.yml`): поднять
`__version__` в `timetable_upload/__init__.py`, закоммитить и поставить тег с
тем же номером:

```sh
git tag v0.1.0 && git push origin main v0.1.0
```

Через несколько минут в Releases появятся архивы для Windows и Linux с
обоими исполняемыми файлами. Тег, не совпадающий с `__version__`, сборку
остановит.
